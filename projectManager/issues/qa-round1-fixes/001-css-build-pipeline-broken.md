# [001] CSS Build Pipeline Broken — Styles Not Bundled

## Metadata
- **Status:** TODO
- **Depends On:** —
- **Blocks:** 002, 003
- **Scope:** M
- **Found in:** QA Round 1 (TC-01.01, TC-02.01, TC-02.02)

## Description

The CSS files in `src/webview/styles/` are never imported into the JavaScript bundle, so esbuild never generates `dist/webview/index.css`. The HTML template in `QuartzEditorProvider.ts` references this file via a `<link>` tag, but it doesn't exist at runtime. **This is the root cause of 3 out of 5 QA failures.**

Without CSS loading:
- All blocks render with browser defaults — no visual separation between blocks ("everything is in one block")
- The drag handle renders inline with text instead of positioned to the left ("brail tab is inside the text box")
- No placeholder styling, no focus indicators, no block spacing

## Root Cause

1. **No CSS imports in webview code.** Files `src/webview/styles/editor.css` and `src/webview/styles/rawBlock.css` exist but are never imported by any `.ts`/`.tsx` file.
2. **esbuild config has CSS loader but nothing to load.** `esbuild.js` sets `loader: { '.css': 'css' }` but since no JS file imports CSS, esbuild never processes it.
3. **`dist/webview/` contains only `index.js` and `index.js.map`** — no `index.css`.

## Technical Notes

### Fix Approach

**Option A (Recommended): Import CSS in the webview entry point**
Add to `src/webview/index.tsx`:
```typescript
import './styles/editor.css';
import './styles/rawBlock.css';
```
esbuild will then bundle these into `dist/webview/index.css` automatically.

**Option B: Explicit CSS entry point in esbuild config**
Add a second entry point in `esbuild.js` for CSS. This is more complex and not needed if Option A works.

### Files to Modify
- `src/webview/index.tsx` — add CSS imports
- Possibly `esbuild.js` — may need adjustments depending on how esbuild handles CSS bundling
